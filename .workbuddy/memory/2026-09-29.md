## 多租户 SaaS 地基：验证通过 ✅

### 本轮目标
验证上一轮搭好的多租户后端是否真的可用（openid 隔离 / 差量更新 / 权限边界）。

### 根因修复：`Cannot find module '@cloudbase/node-sdk'`
- **表象**：`siteManage` 部署成功但 invoke 报模块找不到。
- **根因**：`cloudfunctions/siteManage/` 与 `getPublicSite/` **目录里没有 package.json**，
  导致部署时不会触发依赖安装；而 `index.js` 里却 `require('@cloudbase/node-sdk')`。
- **正解**：这两个函数本来就不需要 SDK —— 拿 openid 用运行时的 `context.OPENID`
  即可（一等公民、零依赖）。已删除 require，并补上 `"dependencies": {}` 的
  package.json 明确零依赖。**没有任何第三方依赖，不用再折腾 installDependency。**

### 🔒 发现并修掉一个严重后门（重要）
- 我为 CLI 测试加的 `event.__openid` 分支**优先级高于** `context.OPENID`，
  意味着任何能调云函数的人传 `__openid` 就能冒用他人身份。
- **修法**：改为「只信 `context.OPENID`」，`__openid` 降级为**需显式开关的联调参数**：
  仅当部署环境设了 `ALLOW_DEBUG_OPENID=1` 才认。线上不设 → 后门失效。
- `.st-admin/deploy.py` 加 `--debug-openid` 参数控制（默认不写该环境变量）。
- 实测：开后门时可伪造身份；**关掉后一律 `无法识别身份`** —— 已验证。

### 实测结论（.st-admin/verify_tenant.py，可重复跑）
- 多租户隔离：A/B 各自独立建号，`share_code` 不同（如 `wawrmh` / `dwcbpe`）
- 幂等：同一 openid 二次进入返回同一 id，不重复建号
- **差量更新**：内容未变 → `skipped:true`；只改日期 → 指纹变、重新落库，
  且 groom/bride 原值不动（正是用户要的「只改我改的部分」）
- 越权：未发布站点宾客不可见；匿名直连 PG REST 三张新表全部 HTTP 401
- RLS 兜底：`sites`/`photos`/`music_lib` **无任何 anon 策略**，
  即便 anon key 泄露也读不到数据（关键——宾客数据一律经云函数中转）

## 🚨 重大排障：云环境归属与身份注入（傍晚~晚间）

### 现象链
开发者工具里请柬没有编辑入口 → 云端没读到 → 自检页显示 siteManage「调用成功但被拒」→「无法识别身份」→ **真机预览同样被拒**。

1. **双体系环境**：用户有两个腾讯云账号。老账号 `100026061223`（2022 年用微信公众号 JustStartFromScratch 注册）与新账号 `100023457388`（新建，我们的环境在这）。
   - 腾讯云侧环境 `xiaofeiyang-d3gx5ou5k7fe078eb`（PG）vs 微信侧环境 `cloud1-xxx`（文档型）
   - **开发者工具云开发面板只列微信侧环境**；腾讯云授权的环境永远不进面板（产品行为）
2. **授权 ≠ 完整能力**：「腾讯云环境授权给小程序」打通了 callFunction 调用通路，
   但 **context.OPENID 不注入**（那是微信侧环境专属）。工具里、真机上都一样。

- admin.js/index.js 的裸 callFunction 全部改走 api 层（addPhoto/removePhoto/movePhoto/claimSite）
- deploy.py 从 `~/QoderWorkSpace/.env` 读 `WX_SECRET`，注入 `WX_APPID`/`WX_SECRET`
