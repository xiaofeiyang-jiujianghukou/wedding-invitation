## 🖥️ 新增：PC 端数据后台（微信扫码登录）

**用户诉求**："那么 PC 端怎么看呢" → "PC 端用微信扫码登陆"。

### 技术卡点与突破（重要，别重走弯路）
1. **HTTP 访问服务走不通**：`routes add` 要域名，而环境默认域名
   `{envId}.service.tcloudbase.com` 属"系统内部域名，不支持手动创建"；
   自定义域名要买 + 备案。→ 放弃 HTTP 路由。
2. **改走 Web SDK 网关**：静态托管域名已在 CORS 白名单，
   `{envId}.api.tcloudbasegateway.com` 可达（401 = 需认证）。
   SDK 用 **v3 UMD CDN**：`https://static.cloudbase.net/cloudbase-js-sdk/3.10.2/cloudbase.full.js`
   （全局 `window.cloudbase`），**不必自己打包**。
   注意：node 里 require 要用 `dist/index.node.cjs.js`（绝对路径 require 目录会走 legacy main = 浏览器版）。
3. **🚨 最大的坑：`EXCEED_AUTHORITY`**。云函数**默认安全规则**是
   `{"*":{"invoke":"auth != null && auth.loginType != 'ANONYMOUS'"}}`，
   **匿名 Web 用户调任何云函数都被拒**。现象极迷惑（小程序端一切正常，只有网页 403）。
   - 查：`cloudbase api tcb DescribeSecurityRule --body '{"EnvId":"...","ResourceType":"FUNCTION"}'`
   - 改：`cloudbase api tcb ModifySecurityRule --body "$(cat .st-admin/security_rule.json)"`
     （`AclTag:"CUSTOM"`，`Rule` 是**字符串化的 JSON**）
   - ⚠️ 老的 `ModifyResourcePermission` 在 **PG 环境直接拒绝**（"does not support PostgreSQL type environments"），别用
   - 规则已落盘 `.st-admin/security_rule.json`（可重现）；`env login set` 只管登录方式开关，**没有**安全规则入口
   - 现有规则：`*` 仍排除匿名，`webLogin` / `adminManage` 显式 `invoke:true`（函数内部自己鉴权）
   - 匿名登录本身是开的（`env login get` → `AnonymousLogin: true`）
4. **不用开放平台扫码**：需要企业主体 + 认证费 + 网站备案，个人主体走不通。
   改用**小程序码**做等价的事。

### 方案：小程序码扫码 + 轮询
```
网页 create    → 云函数生成 scene + 小程序码（指向 pages/webLogin）
用户微信扫码   → 打开小程序确认页 → 点「确认登录」
小程序 confirm → 校验 openid 是站点 owner → 签发 token 存 web_sessions
网页 poll      → 带 scene + secret 取回 token（12h）→ 调 adminManage
```
