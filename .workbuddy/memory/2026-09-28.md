## 追加：动效激活 + 图文对齐（同日第六轮）

### ① 动效是"死"的（根因）
`kenBurns`/`wholeIn` 挂在 `.gallery .swiper-item` 上，CSS animation 播完即停在
最终帧。swiper 切换只是平移新的 swiper-item 进来，**不会有任何动画重新触发**，

live 类跟着索引走：
- `.shot.live` → `wholeIn` 整屏推入 1s（每次轮到都重播）
- `.shot.live .shot-main` → `kenBurns` 6.2s 缓慢推近（scale 1.14→1.02）

- 非当前张静止 `scale(1.04)` + transition 900ms 兜底

时长对齐：`interval 5200 + duration 1000 = 6200ms = kenBurns 时长`，
每张图刚好播完一轮完整动效就被切走，循环无缝。

文案动画重播技巧：`<block wx:for="{{ [config.gallery[galleryIndex]] }}" wx:key="*this">`
—— 单元素循环，索引变 → 数组变 → 节点重建 → `captionIn` 每次切图都重新滑入。

## 追加：8 种运镜动效（同日第七轮）

用户反馈"还是平移"。上一轮的 live 绑定**方向是对的但位置错了**，根因如下。

### ★ 根因：swiper 的 transform 覆盖了动画的 transform
`.shot` 是 `swiper-item` 的**直接子元素**。`<swiper>` 会给它设 `transform`
做滑动动画，而 **CSS 里元素自身 transform 与 `@keyframes` 里的 transform
是同一套机制** —— 外层的 transform 直接把 `scale`/`rotateX` 整个覆盖掉，
只剩 swiper 的平移。所以怎么写动画都"还是平移"。

**修法：多包一层 `.shot-anim`，动画全打在内层。**
swiper 管外层平移，内层动画照常生效，两者叠加 → 画面才有层次。

```xml
<view class="shot">
  <view class="shot-anim fx-{{item.fx}} {{galleryIndex === index ? 'live' : ''}}">
    <image class="shot-blur" .../>
    <image class="shot-main" .../>
  </view>
</view>
```

这是**小程序 swiper 的通用陷阱**，不只是相册——任何想在 swiper-item 里做
缩放/旋转动画的场景都会踩。

### 新增 8 种运镜（config.js 每张一个 `fx` 字段）
| fx | 效果 | 适用 |
|---|---|---|
| `zoom` | 缓慢推近（经典 Ken Burns） | 默认 |
| `pull` | 从贴脸退开 | 静物特写（p02 咖啡 / p13 戒指） |
| `pan-l` / `pan-r` | 镜头左右摇移 | 横向场景（p05 海边 / p10 初雪） |
| `tilt` | 带倾斜缓慢回正，手执感 | 人物对视（p06 / p14 回眸） |
| `rise` | 从下往上抬 | 竖向构图（p08 野餐 / p11 求婚） |
| `bloom` | 暗+糊 → 清晰明亮 | 暗场/特写（p18 雨夜 / p20 星空 / p16 共舞） |
| `sink` | 从上方沉下 | 俯拍感（p07 火车 / p04 婚纱背影） |

时长统一 **6200ms = interval 5200 + duration 1100**，每张刚好播完一轮，无缝。
分布：bloom 4 / zoom 3 / pull 3 / 其余各 2，8 种全部用上。

### 文案动效也跟着换方向（图文"同一口气"）
`.shot-caption` 绑 `fx-cap-{{...fx}}`，按图片运镜选入场方向：
从左滑入（zoom/pull/pan-l）、从右（pan-r/tilt）、从下浮起（rise/sink）、
淡入+字距收拢（bloom）。另加 `.shot-caption::before` 金条 `barGrow` 生长动画。

辅动效：`.shot-blur` 呼吸（blurBreath）、遮罩呼吸（scrimBreath）。

## 追加：栈式轮播 + 八向飞出（同日第八轮，相册动效终稿）

用户反馈："效果还是一样……我期望不是总是往左边飞出，偶尔上偶尔下偶尔左偶尔右，
偶尔左上右下等等～偶尔万花筒等等，根据照片风格自由搭配。"

### ★ 最终根因（比第七轮的 transform 覆盖更根本）
第七轮的「多包一层」只解决了**内层动画被 swiper 覆盖**；但**出画位移本身
由 swiper 的滑动过渡决定，而 swiper 的过渡永远是水平平移**——这是组件行为，
CSS 无法改变方向。用户要求任意方向飞出，包再多层也没用。
**结论：要任意方向飞出/飞入，必须放弃 swiper 的自动推进。**

### 修法：栈式轮播（弃用内层 swiper）
- **双节点渲染**：`wx:if="{{index === galleryIndex || index === galleryPrev}}"`
  只渲染当前张（flyIn）+ 上一张（flyOut）；wx:if 节点重建天然保证动画每次重播，
  不再依赖 live 类绑定
- **JS 推进**：`goGallery(step)` 统一入口，`GALLERY_INTERVAL=6000` 定时器 +
  手势都走它；`galleryPrev` 记录上一张
- **手势**：`galleryTouchStart/End`，`|dx|>|dy|` 且 `|dx|>40`（SWIPE_MIN）才切图，
  竖向放行给外层整屏 stage swiper
- **定时器生命周期**：`onStageChange`（current===2 启动 / 否则停止）、
  手动切换后 `restartGalleryTimer`（防双跳）、`onHide`/`onUnload` 清理

### WXSS 结构（index.wxss 现 790 行）
- 动效拆两层：`.shot-move`（飞行层，dir-xxx + live/out）+ `.shot-anim`（运镜层，fx-xxx + live）
- **8 个飞出 keyframes**：`flyOutLeft/Right/Up/Down/LU/RU/LD/RD`
  （translate ±120~130% + rotate ±7~14deg + scale .72~.8 + opacity 0，1100ms）
- **8 个飞入 keyframes**：方向与飞出相反（左飞的下一张从右进），形成接棒感
- **8 个运镜**：delay 1100ms + 5100ms，与飞行错峰衔接；周期 6000 = 1100 + 5100

## 尾幕下滑回封面手势（用户反馈修复）

用户反馈：尾幕「下滑回封面」没效果。根因两层：
1. WXML 绑了 `onEndingTouchStart/End` 但 `index.js` 里没写这两个 handler（只改了模板没写逻辑）；
2. 即使补上，外层竖向 swiper 的原生拖拽在尾幕只会退回上一幕，且其 `bindchange` 在我们 setData 跳封面之后触发会覆盖跳转。

修法：尾幕手势完全自己接管——`catchtouchmove` 禁掉 swiper 原生拖拽 + 自判下滑（dy>60 且纵向为主 → `setData({current: 0})`）。
新增静态回归脚本 `.st-admin/check_wxml_handlers.py`（校验 WXML 绑定的 handler 在 JS 里都存在，3 页全过）。

已知遗留：祝福墙 `wall-scroll` / RSVP 表单 scroll-view（`flex: 1` 占满下半屏）会吞竖向手势，
这两幕往下滑回上一幕无效（scroll-view 同向嵌套拦截，平台行为）。用户没报这个问题，暂不动，反馈了再做边界回传。
